Restore from a passkey

A passkey holding a backup carries the root itself, which is the whole identity: the certificate is rebuilt from it if the passkey could not hold one, and every contact's pin still matches, because what they pinned is the fingerprint of the public key.

What it does not carry. The ledger and the contact book were not in the backup. This wallet will not know which certificates it has issued — the next one takes a start date later than any it later sees — and it will not know who you know: the contact book comes from an archive, or from your contacts' own next messages.

Protect the vault with a security key

A passkey or security key can replace the passphrase on this device: the vault is re-sealed under a key only the authenticator can derive. Optional, and the passphrase still works.

Which of three you get depends on what the authenticator supports, and the first two differ in kind, not in strength. If it can store a blob, your root goes on it: the passkey alone is then the identity — it restores on a new machine, and anyone who can use that credential can be you. If it can only derive a secret, the authenticator is one of two things needed, the vault file being the other, so losing one of them loses nothing. Either way keep the vault file: an authenticator can be lost, and the backup is what survives that.

This passkey can only gate the vault. It cannot hold a secret, so the wallet would keep the key itself in this browser profile and ask the passkey before using it. Anyone with this profile could read that key without the passkey, so what protects the vault at rest is the passphrase, as it was. The exported vault file is unchanged either way.
